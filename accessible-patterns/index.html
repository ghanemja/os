Accessible patterns

Correct ARIA markup and keyboard handling for common widgets, following the WAI-ARIA Authoring Practices. Each pattern is one small vanilla JavaScript module with no dependencies, plus a demo page and a README that documents its keyboard interaction and ARIA roles, states and properties.

  • Modal dialog

    Focus trap, Escape to close, inert background, focus returns to the trigger.

    • dialog
    • aria-modal
    • inert

  • Tabs

    Arrow keys, Home/End, automatic or manual activation, horizontal or vertical.

    • tablist
    • tab
    • tabpanel

  • Disclosure

    A button that shows and hides a section.

    • aria-expanded
    • aria-controls

  • Accordion

    Stacked sections that open one at a time or several at once, with arrow keys between headers.

    • region
    • aria-expanded

  • Menu button

    A button that opens a menu of actions, with arrow keys and type-ahead.

    • menu
    • menuitem
    • aria-haspopup

  • Combobox

    Autocomplete input with a listbox popup, using aria-activedescendant.

    • combobox
    • listbox
    • option

  • Toggle button

    An on/off button with a constant label.

    • aria-pressed

  • Tooltip

    Shows on focus and hover, is hoverable, and Escape dismisses it.

    • tooltip
    • aria-describedby

  • Alert and live regions

    Polite and assertive announcements that work reliably, including for repeated messages.

    • alert
    • status
    • aria-live

  • Skip link

    "Skip to main content" that really moves focus.

    • WCAG 2.4.1

The demos use ES modules, so open them over HTTP, for example with npx serve or python3 -m http.server. Browsers block module scripts on file:// pages.
